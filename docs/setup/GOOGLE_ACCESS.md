# Google access setup for the personal React MVP

This setup connects the deployed Python backend directly to the owner's Google account. React never receives Google credentials or raw Gmail bodies, and Codex plugins or MCP servers are not application dependencies.

Do not send the OAuth client JSON, refresh token, or private email contents in chat or commit them to Git.

## Permission boundary

The active Gmail phase requests exactly:

- `https://www.googleapis.com/auth/gmail.readonly` - read messages matching the approved Gmail query; it cannot modify, send, or delete mail.
- `https://www.googleapis.com/auth/drive.file` - create and update files created by this app; it does not request access to every Drive file.

Keep the app limited to the owner's Google test account during the personal phase. A public or multi-user release requires a separate OAuth verification, privacy, and security workstream.

## Google Cloud checklist

1. Open the existing Google Cloud project.
2. Enable Gmail API and Google Drive API. Google Sheets API is needed only by historical tracker scripts, not the current Gmail run.
3. Under Google Auth Platform, confirm Branding and Audience are configured.
4. Keep the owner Gmail account listed as a test user while the app remains in Testing.
5. Under **Data Access**, confirm the two exact scopes above.
6. Keep the OAuth client application type as **Web application**.
7. Add this exact local authorized redirect URI:

   ```text
   http://localhost:8000/api/auth/google/callback
   ```

8. Save. Google Cloud and `JOB_HUNT_OAUTH_REDIRECT_URI` must match exactly, including scheme, host, port, and path.
9. Keep the downloaded client at `D:\Projects\job_hunt\oauth-client.json`, or use a private external path through the environment variable below. The project path is Git-ignored.
10. Keep the Gmail label tree:

   ```text
   Job_Alerts/
     LinkedIn   -> Job_Alerts/LinkedIn
     Naukari    -> Job_Alerts/Naukari
     link_test  -> Job_Alerts/link_test
     nau_test   -> Job_Alerts/nau_test
   ```

The production query generated by the UI is:

```text
{label:Job_Alerts/LinkedIn label:Job_Alerts/Naukari} newer_than:30d
```

## Private runtime credential and state files

- `oauth-client.json`: Web OAuth client; Git-ignored and never sent to React or Drive.
- `JOB_HUNT_GOOGLE_CREDENTIALS`: optional override path to an external client JSON.
- `JOB_HUNT_OAUTH_REDIRECT_URI`: optional callback override; defaults to `http://localhost:8000/api/auth/google/callback`.
- `JOB_HUNT_FRONTEND_URL`: optional post-OAuth UI URL; defaults to `http://localhost:8000`.
- `.secrets/google_token.json`: local-default generated user access/refresh token; Git-ignored, server-side, and not encrypted locally.
- `.secrets/google_oauth_state.json`: local-default short-lived OAuth state and PKCE verifier, consumed after one callback.
- `.secrets/app_state.json`: local-default app-owned Drive identifiers and latest run metadata.
- `.secrets/gmail_seen_state.json`: local-default normalized job fingerprints; synchronized to app-owned Drive `Job Hunt/Source`.
- `.secrets/source_cache/Company_Source_Registry.xlsx`: local-default validated cache of the authoritative app-owned Drive registry; it is replaced only after a changed Drive revision passes validation.

`.secrets` is not a Streamlit folder. For deployment, set `JOB_HUNT_RUNTIME_DIR` to an
encrypted persistent private mount; the same filenames are stored under that directory.
Optional `JOB_HUNT_OUTPUT_DIR` and `JOB_HUNT_GMAIL_RUN_DIR` settings move generated
artifacts. `JOB_HUNT_REGISTRY_PATH` moves the local registry cache only; it does not replace
the Drive workbook as the source of truth.

An `.env` file is not required. Environment variables apply only to the terminal in which they are set.

## PowerShell commands

The checked-in default path needs no credential environment variable:

```powershell
cd D:\Projects\job_hunt
$env:JOB_HUNT_OAUTH_REDIRECT_URI = "http://localhost:8000/api/auth/google/callback"
.\.venv\Scripts\python.exe -m uvicorn job_hunt.api.main:app --host 127.0.0.1 --port 8000
```

To keep the OAuth client somewhere else:

```powershell
$env:JOB_HUNT_GOOGLE_CREDENTIALS = "C:\private\path\oauth-client.json"
$env:JOB_HUNT_RUNTIME_DIR = "C:\private\job-hunt-runtime"
```

Use the virtual environment Python directly to avoid PowerShell activation-policy problems.

## First React connection and real Gmail check

1. Open `http://localhost:8000`.
2. Confirm the connection card says Google is disconnected or requires reconnection.
3. Select **Connect** or **Reconnect**.
4. Choose the Gmail test-user account and approve the displayed read-only Gmail and app-created Drive-file permissions.
5. Google returns to the React application; confirm **Google connected**.
6. Keep the default production labels or use `link_test` and `nau_test` for a smaller fixture run.
7. Select Gmail in **Search** and run the selected source.
8. Confirm the rows appear in **Results** and are labelled temporary; no dated Excel file should be created. Save one row and confirm it appears in **Applications** after refresh.
9. Select **Save for later** or change one application status. Reload the site and confirm only that tracked job returns from `Job Hunt/Source/application_queue.json`.

The first tracked job creates or reuses `Job Hunt/Source/application_queue.json`. Searching alone does not create a dated folder or workbook, invoke an LLM, modify Gmail, or submit applications. Existing historical Gmail workbooks remain available from the Results screen.

To correct a careers or portal URL, edit `Company_Source_Registry.xlsx` inside the app-owned
Drive `Job Hunt/Source` folder, save it, and select **Refresh registry** in Search. A valid
changed workbook replaces the local cache; an invalid or unavailable Drive copy leaves the
last validated cache active and displays a warning.

## Private hosting checkpoint

Do not expose the local FastAPI process directly to the public internet. A private deployment needs:

- an exact HTTPS OAuth callback in Google Cloud and `JOB_HUNT_OAUTH_REDIRECT_URI`;
- `JOB_HUNT_FRONTEND_URL` set to the private HTTPS application URL;
- a stable secret in `JOB_HUNT_SESSION_SECRET` and `JOB_HUNT_COOKIE_SECURE=true`;
- private access control in front of the app;
- persistent encrypted storage for the Google token and application state;
- a backup and token-revocation procedure.

Those are deployment decisions after the real local Gmail parity run, not part of the current migration.
